# Contributing to COSL

Thank you for helping make open-source learning more accessible. Contributions of every size are welcome, including documentation, testing, bug reports, lab ideas, design feedback, and code.

## Before you start

1. Check whether you are contributing to an **educational lab** under `@codemolabs` (focused on guided learning, testing, and skill building) or a **production product** under `@codemoteams` (focused on production stability, performance, and release engineering).
2. Read the repository README and any project-specific contribution notes.
3. Check open issues and discussions to avoid duplicating work.
4. For a substantial change, open an issue or discussion first so maintainers and contributors can agree on scope.
5. Do not include secrets, personal data, copyrighted material you cannot license, or files you are not permitted to share.

## A good contribution flow

1. Fork the repository and create a focused branch, for example `docs/fix-setup-guide` or `feat/add-example`.
2. Make a small, purposeful change that solves one problem.
3. Run relevant tests, checks, or the lab steps; explain anything you could not run.
4. Update documentation when behavior, setup, or instructions change.
5. Open a pull request with a clear title, context, what changed, how it was tested, and any relevant issue links.
6. Respond constructively to review feedback and keep the discussion respectful.

## Pull request checklist

- [ ] The change is focused and described clearly.
- [ ] Tests or manual verification are explained.
- [ ] Documentation is updated where needed.
- [ ] No secrets, private data, or unauthorized third-party material are included.
- [ ] I have the right to submit this work under the repository's stated license, if any.
- [ ] The contribution complies with our [Code of Conduct](CODE_OF_CONDUCT.md).

## Commit and issue guidance

Use descriptive commit messages and include enough context for someone new to the project. In issues, provide steps to reproduce, expected and actual behavior, relevant environment details, and sanitized logs where applicable. Do not post credentials, access tokens, or private user information.

## First-time contributors

You do not need to be an expert. Start with a question, typo, documentation clarification, test, or clearly scoped issue. Ask for help when blocked. Maintainers may label suitable tasks as beginner-friendly, but labels and response times vary by repository.

## Review and merge

Submitting a contribution does not guarantee acceptance. Maintainers may request changes, defer work, or close contributions that are out of scope, unsafe, unmaintained, or inconsistent with project goals. Reviews aim to improve the work, not judge the contributor.

Project Maintainers exercise responsibilities only within their assigned projects and repositories. Organization-wide authority, administrative access and COSL leadership responsibilities are assigned separately under [ORGANIZATION.md](ORGANIZATION.md).

## Questions & Support

For help and general questions, consult [SUPPORT.md](SUPPORT.md), use the repository's Issues or Discussions, or join our [Discord server](https://discord.gg/wD9d5Er7a). For security vulnerabilities, consult our [Security Policy](SECURITY.md) and contact [cosl@codemoteams.org](mailto:cosl@codemoteams.org) privately.

## Learning and Professional Certification

COSL encourages contributors to develop their technical skills through official learning resources and practical open-source experience.

Recommended resources:
- [GitHub Skills](https://learn.github.com/skills)
- [GitHub Credentials](https://learn.github.com/credentials)
- [GitHub Courses](https://learn.github.com/courses)
- [Microsoft Learn](https://learn.microsoft.com/training/)

Under the proposed COSL certification framework, the mandatory GitHub Foundations examination requirement applies to designated senior leadership and organization-level authority holders. It does not apply to ordinary contributors and learners, and becomes binding only after formal adoption. Senior technical leads should pursue relevant role-specific credentials where applicable.

A completed course, learning path, or GitHub Skills exercise is a learning achievement, not a professional certification.

See [CREDENTIALS.md](CREDENTIALS.md) for the complete COSL Learning, Credentials & Certification Policy.
