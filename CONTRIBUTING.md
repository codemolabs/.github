# Contributing to COSL

Thank you for helping make open-source learning more accessible. Contributions of every size are welcome—documentation, testing, bug reports, lab ideas, design feedback, and code.

## Before you start

1. Read the repository README and any project-specific contribution notes.
2. Check open issues and discussions to avoid duplicating work.
3. For a substantial change, open an issue or discussion first so maintainers and contributors can agree on scope.
4. Do not include secrets, personal data, copyrighted material you cannot license, or files you are not permitted to share.

## A good contribution flow

1. Fork the repository and create a focused branch, for example `docs/fix-setup-guide` or `feat/add-example`.
2. Make a small, purposeful change that solves one problem.
3. Run relevant tests, checks, or the lab steps; explain anything you could not run.
4. Update documentation when behavior, setup, or instructions change.
5. Open a pull request with a clear title, context, what changed, how it was tested, and any relevant issue links.
6. Respond constructively to review feedback and keep the discussion respectful.

## Pull request checklist

- [ ] The change is focused and described clearly.
- [ ] Tests or manual verification are explained.
- [ ] Documentation is updated where needed.
- [ ] No secrets, private data, or unauthorized third-party material are included.
- [ ] I have the right to submit this work under the repository's stated license, if any.
- [ ] The contribution complies with our [Code of Conduct](CODE_OF_CONDUCT.md).

## Commit and issue guidance

Use descriptive commit messages and include enough context for someone new to the project. In issues, provide steps to reproduce, expected and actual behavior, relevant environment details, and sanitized logs where applicable. Do not post credentials, access tokens, or private user information.

## First-time contributors

You do not need to be an expert. Start with a question, typo, documentation clarification, test, or clearly scoped issue. Ask for help when blocked. Maintainers may label suitable tasks as beginner-friendly, but labels and response times vary by repository.

## Review and merge

Submitting a contribution does not guarantee acceptance. Maintainers may request changes, defer work, or close contributions that are out of scope, unsafe, unmaintained, or inconsistent with project goals. Reviews aim to improve the work, not judge the contributor.

## Questions & Support

For help and general questions, consult [SUPPORT.md](SUPPORT.md), use the repository's Issues or Discussions, or join our [Discord server](https://discord.gg/wD9d5Er7a). For security vulnerabilities, consult our [Security Policy](SECURITY.md) and contact [cosl@codemoteams.org](mailto:cosl@codemoteams.org) privately.
